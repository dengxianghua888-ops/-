# Reader Engine：读者驱动机制分析

## 一、核心驱动力矩阵

| 驱动力 | 强度 | 触发位置 | 持续时长 |
|--------|------|----------|----------|
| 正义补偿欲 | 10/10 | Ch1（得知被宣告死亡） | 全文 |
| 信息差好奇 | 9/10 | Ch1-3（还有什么真相？） | Ch1-Ch4 |
| 公开羞辱期待 | 9.5/10 | Ch4末（"老公，结婚这么大的事…"） | Ch5-Ch8 |
| 量化对比爽感 | 9/10 | Ch2起（每组新对比） | Ch2-Ch7 |
| 法律制裁期待 | 8.5/10 | Ch8（三条声明） | Ch8-Ch9 |
| 母子新生治愈 | 7/10 | Ch9（积木场景） | Ch9 |

## 二、信息差引擎设计

### 第一层信息差（Ch1）
- **读者知道 > 新娘知道**: 读者知道女主还活着，新娘以为"前妻已死"
- **驱动力**: "她什么时候揭穿？"

### 第二层信息差（Ch2-3）
- **女主逐渐知道 > 读者同步获知**: 百万分红、戒烟真相、做饭真相
- **驱动力**: "还有多少真相没被揭开？"

### 第三层信息差（Ch4-8）
- **女主知道全部 > 在场所有人知道**: 女主掌握全局，一点一点释放
- **驱动力**: "她什么时候说出下一条？对方什么反应？"

## 四、情绪货币（读者为什么付费）

### 付费点1（约2500字处，Ch3末）
**情境**: 得知丈夫编造妻儿已死——信息差达到极端
**读者心理**: "她一定要让他死！我必须看到她怎么做！"

### 付费点2（约4500字处，Ch5中）
**情境**: 舞台夺麦刚开始，真相刚说出一半
**读者心理**: "全场反应呢？新娘怎么办？他怎么圆？"

### 付费点3（约6500字处，Ch7-8交界）
**情境**: 假证暴雷，三条清算即将出口
**读者心理**: "法律会怎么判？能判几年？"

## 五、读者心理模型

### 目标读者画像
- 25-40岁女性，已婚或有婚恋经验
- 在婚姻中有过被忽视/不被重视的体验
- 对"隐性剥削"（看似没问题但长期吃亏）高度敏感
- 需要"替代性正义"——看到有人替自己出了气

### 情绪需求满足路径
```
共鸣（"我也经历过类似的忽视"）
→ 代入（"如果是我会怎么做"）
→ 震惊（"居然连孩子都编造为死了"）
→ 愤怒（"这一家子太恶心了"）
→ 期待（"她一定要让他们付代价"）
→ 爽快（"打得好！说得好！"）
→ 正义感满足（"法律判了！活该！"）
→ 治愈（"母子重新开始，真好"）
```

## 六、防退出设计

| 退出风险点 | 防退出机制 |
|-----------|-----------|
| Ch1末（信息差建立后犹豫是否继续） | "就写'诈尸的前妻'"——幽默+暗示即将行动 |
| Ch3中（量化对比可能产生疲劳） | 每组对比用不同载体（钱/物/行为/时间），避免重复感 |
| Ch5后（揭穿已完成，还有什么？） | 假证暴雷+法律清算——新的故事层 |
| Ch8后（高潮已过） | 快速收束，不拖泥带水 |
