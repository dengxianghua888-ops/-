# Reader Engine

## 核心读者按钮
- 按钮1：公开羞辱
  - 民政局抢证、婚礼伴娘服、假证糊弄、低配婚礼。
- 按钮2：当场翻桌
  - 女主不是回家哭，而是现场拉哥哥领证。
- 按钮3：高位现任
  - 现任是哥哥、继承人、提前准备婚纱的人。
- 按钮4：旧爱火葬场
  - 情感失去、婚育反噬、家族失势、事业破产。
- 按钮5：绝不回收
  - 全文不给前任一丝“还有机会”的窗口。

## 读者追读回路
1. 开场震惊：怎么会有人在民政局把未婚妻换成闺蜜？
2. 立刻上瘾：女主竟然当场换新郎？
3. 持续上头：哥哥到底是真娶还是救场？
4. 付费冲动：家宴认嫂，前任如何社死？
5. 深层停留：前任还会失去什么？
6. 终局满足：女主真的不回头了吗？

## 爽点分发机制
- 首爽点：原句镜像回敬
- 第二爽点：现任正式表白接住
- 第三爽点：婚礼当天前任被放鸽子
- 第四爽点：肖家家宴认大嫂
- 第五爽点：假证与伴娘服旧账公开
- 第六爽点：流产离婚破产连环反噬
- 第七爽点：年夜饭一句“大嫂”完成地位盖棺

## 付费点设计逻辑
- 付费点1：家宴前0.5步
  - 用户最想看前任何时知道自己被替换。
- 付费点2：认嫂后旧账爆雷
  - 用户不仅要看身份反转，还要看施害细节被长辈知道。
- 付费点3：前任婚育与事业连续崩盘
  - 用户要的不是一巴掌，是持续失血。
- 付费点4：年夜饭切割
  - 用户要确认女主真的不回头。

## 信息差引擎
- 读者早知道、前任晚知道：
  - 真领证
  - 真婚礼对象
  - 哥哥早有心意
  - 债务会被追偿
- 女主知道、长辈晚知道：
  - 假证
  - 伴娘服羞辱
  - 闺蜜先领证
- 反派彼此晚知道：
  - 江柔对姜晚的嫉妒动机
  - 肖奈真正放不下的是姜晚

## 情绪曲线控制
- 0%-15%：高辱点 + 立刻反打
- 15%-35%：补沉没成本，抬女主委屈值
- 35%-60%：现任接住，婚礼反压，前任误判
- 60%-75%：家宴认嫂，身份核爆
- 75%-90%：婚育线、家族线、事业线三连反噬
- 90%-100%：平静切割，终局落稳

## 人物功能分配
- 女主：情绪代偿入口，也是边界重建样板
- 前任：羞辱制造机 + 后悔素材库
- 现任：高位托底器 + 执行型偏爱
- 闺蜜：背刺加速器 + 因果承载体
- 肖家父母：社会认证装置
- 姜氏/公司债务：把感情账落地成现实账

## 高转化句式模板
- “反正X不是Y吗？我和谁Z不都一样？”
- “你的位置，不在这儿。”
- “你大嫂进门了，还不打招呼？”
- “我不恨你，我只是不在乎你了。”
- “太晚了。”
- “欠我的，你得还。”

## 改编时的转化警报
- 若前300字没有“双重反常”，点击率会掉。
- 若现任上线太晚，读者会误判成虐女主。
- 若前任崩得太快，火葬场不够烧。
- 若后半只剩商战，付费欲会掉。
- 若结尾写成和解，会直接背叛核心读者。
