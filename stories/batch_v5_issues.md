## 问题列表

### P1: 初始生成字数严重不足

**现象**：每篇故事首次生成的 nonspace chars 通常在 5000-7000，远低于 10000 下限。
**影响**：需要 3-5 轮逐章扩写才能达标，大幅增加产线耗时。
**根因**：LLM 在单次生成时倾向于压缩叙事，跳过细节描写和过渡段落。
**建议**：
- 在 beat-bible 中为每个 beat 设置 target_chars_min/max，生成时逐 beat 检查
- 考虑分 beat 独立生成再拼接，而非一次性生成全文
- 在 prompt 中明确要求"每个场景至少 X 行"

### P2: 行均偏长（avg_line_chars 系统性偏高）

**现象**：5 篇中有 4 篇初始 avg_line_chars 超过源文 ceiling，需要后处理拆行。
**影响**：需要额外的行拆分步骤，且拆分可能破坏引号完整性。
**根因**：模型生成时倾向于写完整长句，而源文风格是"一句一段"的碎片化叙事。
**建议**：
- 在生成 prompt 中强调"每个句号后换行"
- 自动拆行脚本需要处理引号边界（避免把引号内容拆到两行）
- 考虑在 style-dna 中提取"断句模式"作为约束

### P3: 问号密度需要手动调节

**现象**：初始生成的问号密度通常远低于源文（Story #4 从 5.82 降到 0.4 再调到 1.4；Story #5 从 1.0 调到 2.58）。
**影响**：需要手动添加/删除问号，且容易过度修正。
**根因**：
- 模型倾向于使用陈述句
- 源文中大量问号来自内心独白和反问句，模型不会主动生成这类句式
**建议**：
- 在 rhythm_metrics 检查后，自动化"问号补充"步骤
- 建立问号插入模板库（"是不是？""为什么？""怎么会？"等）
- 在 beat-bible 中标注哪些 beat 适合使用疑问句

### P4: 自动拆行脚本破坏引号完整性

**现象**：Story #5 拆行后出现引号被拆到两行的情况（如 `"陆辰。别站着了。\n"她催我。`）。
**影响**：需要手动修复，增加人工干预。
**根因**：拆行脚本按句号位置拆分，未考虑引号配对。
**建议**：
- 拆行逻辑需要感知引号状态（在引号内不拆分）
- 或者只在非对话行进行拆分

### P5: 都市情感类冲击密度偏低

**现象**：Story #5 冲击密度仅 1.99/k，低于 floor 3.4（但 gate 仍 pass）。
**影响**：情节张力可能不足，读者留存率可能受影响。
**根因**：都市情感类故事的冲突主要是"冷暴力"和"情感忽视"，不产生 physical_violence 或 verbal_attack 类型的 impact。
**建议**：
- 扩展 impact 检测类别，增加"情感冲击"类型（如被忽视、被替代、被嘲笑）
- 或者在 beat-bible 中为情感类故事设计更多对抗性对话

### P6: Edit 工具字符串匹配失败

**现象**：多次 Edit 操作因 old_string 不匹配而失败，需要重新 Read 文件。
**影响**：增加操作轮次，浪费 context。
**根因**：前一次编辑改变了文件内容，但 context 中缓存的文件状态未更新。
**建议**：
- 每次编辑前先 Read 目标区域
- 或使用行号定位而非字符串匹配
