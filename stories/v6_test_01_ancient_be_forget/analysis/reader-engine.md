# Reader Engine — 《东瓶西镜放，恨不能遗忘》

## 核心驱动力（为什么读者停不下来）

### 1. 信息差悬念引擎

读者从第一句就知道女主有隐藏身份，但男主不知。这创造了一种**"等着看你被打脸"的期待感**，贯穿全文前70%。

- 信息差建立：第1句
- 信息差维持：前65%
- 信息差引爆：70%处（大婚驾到）
- 引爆后续波：75%（林楚楚自爆）

### 2. 情绪债累积引擎

每一层新的压迫都在读者心中记下一笔"必须偿还"的债：

| 债序 | 内容 | 读者心理 |
|------|------|---------|
| 1 | 告知另娶 | "渣，但还能忍" |
| 2 | 烧小院 | "太过分了" |
| 3 | 杀子 | "不可原谅" |
| 4 | 灌红花 | "必须死" |
| 5 | 爬天梯 | "怎么还有？？" |
| 6 | 凤冠给别人 | "我等着你跪" |

债越多，清算时的爽感越强。本文的高明在于：**在9000字内累积了6层债**，密度极高。

### 3. 身份碾压期待引擎

读者全程知道"她是公主"，所以每一次她被羞辱为"村妇""下贱坯子"，都在积蓄一种**"等你知道她是谁"的爽感势能**。

关键设计：
- 陆北辰说"村妇怎配为我世子夫人"→ 你连给她提鞋都不配
- 林楚楚说"你一个下贱坯子"→ 你跪着的才是真公主
- 青黛说"秀着金凤纹的冠服有几个人敢穿"→ 势能释放

### 4. 微钩子密度

每800-1200字必有一个新信息/新打击/新转折，保证碎片化阅读场景下每次打开都有收获：

- 800字：他的身份（定北侯世子）
- 1600字：与林楚楚有夫妻之实
- 2400字：生辰日苟合
- 3200字：林楚楚可能有孕+要求打掉女主孩子
- 4000字：下药杀子
- 4800字：灌红花
- 5600字：爬天梯
- 6400字：天灯信号
- 7200字：公主驾到
- 8000字：当众控诉
- 8800字：林楚楚自爆
- 9600字：不原谅结局

## 付费点设计（番茄场景）

### 第一付费墙（约3000-3500字）

**位置**：杀子段结束，女主昏迷，林楚楚闯入
**钩子**："房门被人一脚踹开，林楚楚带着几个婆子闯了进来。"
**读者心理**：她要对昏迷的女主做什么？

### 第二付费墙（约5500-6000字）

**位置**：天灯升起，女主决定大婚日行动
**钩子**："希望明日，你们不要后悔。"
**读者心理**：她要怎么做？大婚会发生什么？

### 第三付费墙（约7000字）

**位置**：公主仪仗到门口，尚未进入
**钩子**："议论声刚落，公主的仪仗已经到了门口。"
**读者心理**：他看到她时什么反应？

## 读者心理满足清单

- [x] 替代性复仇快感（大婚清算）
- [x] 身份反差爆发的碾压爽（凤冠加身）
- [x] "不原谅"的清醒共鸣（现代女性价值观投射）
- [x] 迟来的悔恨（陆北辰的追悔）
- [x] 亲情温暖补偿（父皇/皇兄）
- [x] 因果报应的公正感（林楚楚被同样对待）
- [x] 独立自主的生活（种地/不需要谁）

## 防流失设计

- 前300字即建立双重信息差，不给读者退出窗口
- 压迫层级递进而非重复，避免"同质化疲劳"
- 清算段节奏极快（短句连击），一旦开始就不允许读者放下
- 清算后不立刻结束，用父女温情修复读者情绪创伤
- 结尾留白（他住河对岸）给读者讨论空间→促转发
