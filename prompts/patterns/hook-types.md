# Hook 类型库（Hook Types）— V3

> 新媒体爆款的"黄金前 300 字"必须锁住读者眼球。本文件归纳 4 种高复用 Hook 原型,每种给出:识别信号 / 结构模板 / 代表摘录 / 改编要点 / 审校 checklist。dissector 用它识别 hook 类型并打分;adapter 的 blueprint 第 1 Beat 必须显式标注 hook type;writer 写首 300 字时照此模板。
>
> 本库是对 `prompts/dissector.md` 原有"黄金前三段"法则的细化。

## H1 · 倒叙冲突式

### 识别信号

- 开篇第一句就是全文**最极端的冲突结果**,后续才倒叙过程
- 前 200 字内出现"被 X 的第 N 天""我死的时候""全家死了"这类极端状态
- 叙述是**冷静陈述事实**,不是抒情

### 结构模板(前 300 字)

```
句 1(极端冲突):【极端状态陈述,单句,≤20 字】
句 2-3(补充信息):【身份/场景补足,2 句,短句】
句 4-6(第一个微冲突细节):【具体动作/对话,3-5 句】
句 7-9(悬念勾出):【结尾留一个"为什么""怎么回事"的钩子】
```

### 代表摘录

> ——《海关包》:"我收到海关电话,说我货物涉嫌走私。价值三千万的'爱马仕铂金包'。"
> ——《末世让我滚出基地后》:"末世降临,我是庇护所唯一的吞噬物。每天的任务就是吃饭、睡觉、打游戏。/ 直到所长的亲女儿,她砸了我的游戏机,把我拖出安全屋,扔进满是辐射尘和变异兽的废墟里。"

### 等价改编要点

- 第一句的**极端状态词**可换,但极端级别不能降(原文"死""灭门""走私"——改编不能换成"我被冷落")
- 倒叙的触发点必须在前 300 字内完成,不能拖到第 500 字
- 不要用"曾经..."开头——那是抒情,不是倒叙冲突

### 审校 checklist

- [ ] 第 1 句在 ≤25 字内完成极端冲突陈述
- [ ] 前 300 字无形容词堆砌,全是具体事实
- [ ] 300 字末尾有明确悬念钩子(一个未解的问号)

## H2 · 死亡反讽式

### 识别信号

- 开篇或前 200 字内明确"我死了/被害了",第一人称继续叙述
- 叙述人已无行动能力,只能"看""听""想"
- 极端的温度反差(最爱的人在做最残忍的事)

### 结构模板(前 300 字)

```
句 1-2(死亡事实):【"我死了"+ 致死方式,≤30 字】
句 3-5(场景沉浸):【死后所在/看到的第一个场景,短句群】
句 6-8(施害者冷冽对比):【施害者的动作/表情描写,强反差】
句 9-12(信息差炸弹埋伏):【只有死者知道的关键信息,埋在读者心里】
```

### 代表摘录

> ——《我死后老公亲手解剖了我的尸体》:"我被未婚夫的疯狂追求者从顶楼推下时,脑子里只有一个念头。别伤到我的肚子。/ 他的手指稳定而有力,没有半分迟疑。白布被猛地掀开。我狼狈不堪的尸身,就这么毫无遮拦地暴露在惨白的灯光下。"

### 等价改编要点

- 死因可换(坠楼/中毒/刺杀/车祸),但"被**最亲近的人**背叛致死"是核心
- 信息差炸弹(怀孕/财产/真相)必须在前 300 字内**暗示**,不是明说
- 叙述语气要冷静到近乎冷漠——读者的痛感来自"她都不哭了"

### 审校 checklist

- [ ] 前 200 字出现明确"我死了/已死"的陈述
- [ ] 施害者的动作/表情被具体描写(不是抽象"他很冷酷")
- [ ] 存在一个只有死者知道的信息(为后续引爆用)
- [ ] 全段无抒情/控诉,只有事实

## H3 · 预言/违和式

### 识别信号

- 开篇有一个"常识外"的设定(预言/弹幕/重生/穿越/异象)
- 前 300 字内出现一个**违和感**:看起来应该 A 的事实是 B
- 读者的第一个反应是"为什么?"而不是"好惨"

### 结构模板(前 300 字)

```
句 1-2(违和前提):【非常规的设定/事实陈述】
句 3-5(日常化处理):【把违和当成日常,加重违和感】
句 6-9(第一个具体矛盾):【违和带来的矛盾具体显影】
句 10-12(悬念):【留一个核心谜团】
```

### 代表摘录

> ——《姐姐新生之时是我的死亡之日》:"爸妈突然能看见空气中的弹幕,弹幕预言我姐温以初会因我被家人偏爱而抑郁。/ 从此全家集体表演爱姐姐、厌我。/ 我 7 岁那年,在雨天被独自关在门外,发烧四十度。"
> ——《娘亲脱离世界后父皇悔疯了》:"我娘在为父皇生下第八个皇子被贵妃溺死后,她突然不闹了。/ 她只是抱着我,说她要走了。"

### 等价改编要点

- 违和的"常识外设定"必须是**故事核心机制**,不是装饰(如弹幕预言是剧情的锚)
- 不要在前 300 字内**解释**违和——让读者带着谜团往下读
- 古言的留白感来自不解释,现代反转的违和感来自"平静地说出不该平静的事"

### 审校 checklist

- [ ] 前 300 字内至少 1 个违和/预言/异象
- [ ] 违和与全文核心机制挂钩(不是装饰)
- [ ] 前 300 字内不解释违和的原理(留白)

## H4 · 空降揭露式

### 识别信号

- 开篇有一个"主角的秘密计划"陈述,读者站在主角视角等着看反应
- 前 300 字展开一个**即将揭晓的场景**(婚礼/颁奖/公司大会)
- 主角身份/地位与场上其他人**存在巨大反差**,但暂不揭穿

### 结构模板(前 300 字)

```
句 1-3(秘密计划):【主角的隐瞒与动机,冷静陈述】
句 4-7(场景铺展):【即将揭晓的舞台,常含名利场元素】
句 8-11(期待破裂):【主角发现事情不对劲】
句 12-15(情绪翻转):【从期待 → 冷笑/清醒,为揭露埋雷】
```

### 代表摘录

> ——《瞒着老公空降公司》:"我辞掉了年薪三百万的工作。瞒着所有人。包括我的丈夫。只为了给他一个惊喜。/ 可他抬起手,朝着舞台的侧方伸了过去。/ 从侧台的阴影里,走出来一个女人。"

### 等价改编要点

- 秘密计划的动机必须是**爱**/信任/期待(正向情绪),才有后续反转的落差
- 场景要有明确的"舞台"(婚礼/会议/典礼/评审),场上有观众
- 期待破裂后主角的反应不是痛哭,而是**冷静+微笑+准备反击**

### 审校 checklist

- [ ] 前 100 字交代秘密计划(动机明确)
- [ ] 前 200 字建立"舞台"场景
- [ ] 前 300 字完成"期待 → 破裂 → 冷静"的三段情绪切换
- [ ] 主角态度从正向情绪 → 冷静,**不写崩溃**

## Hook 强度评分(dissector 使用)

对一个 Hook 从 4 个维度打分,总 10 分:

| 维度 | 说明 | 满分 |
|------|------|------|
| **极端度** | 冲突级别是否到生死/灭门/倾家荡产级别 | 3 |
| **信息密度** | 前 300 字塞了多少反差/反转/秘密 | 3 |
| **悬念尖锐度** | 结尾的钩子是否让人必须往下读 | 2 |
| **节奏利落度** | 是否全短句/无形容词堆砌/无 AI 味 | 2 |

> workspace.yaml 的 `hook_min_score: 7` 是对这 10 分制的下限要求。改编 blueprint 的 Beat 1 必须显式写出目标 hook type 和预期分数。
